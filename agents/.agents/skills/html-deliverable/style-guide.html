[ DECISIONS ]
What changed in v13, and why
There is one button. It is the square sweep. Outline is the default, .solid inverts it for a single primary action per view, and .btn.sm is the same button at chrome scale for topbars and dense UI. That is the entire button system. A filled non-sweeping chrome variant was tried and deleted — a second personality in the chrome is exactly the inconsistency that makes an interface feel assembled rather than designed. If a bar needs an action, it gets .btn.sm. Nothing else is permitted.
The accent is mode-aware, and that is deliberate. #e07000 on light, #ff8100 on dark. This was reversed twice during the v4–v6 review and landed here on purpose after all three options were rendered side by side. A single value was tried in both directions: #ff8100 everywhere is too weak on cream (2.30:1), and #e07000 everywhere loses the fire in dark (6.12:1 vs 7.91:1). Do not "fix" this back to a single value. It is not an oversight.

[ TYPE ]
Geist Mono · variable 300–700

Body — mode-aware weight

Most outages are not surprises. They are known failure modes that nobody had budget to fix, discovered at the worst possible hour by the person least equipped to fix them.

18px / 1.56 · weight · colour --ink-body

Why the weight differs by mode. Light-on-dark type optically erodes, so the same weight reads thinner in dark than light. Dark runs 450, light runs 400. Geist Mono is a true variable font on the 300–700 axis, so any value between is available — you are not limited to 400/500 steps.

Dimming is kept. --ink-body stays dimmer than full ink in both modes; the added weight compensates rather than replaces it.

[ BUTTONS ]
Square-sweep — the only button · 1.5px
One button personality across the site. 1.5px accent border, 0px corners, transparent ground; on hover an accent square sweeps in from the bottom-right and the label flips to black. Chrome and topbars use .btn.sm — the same sweep, the same border weight, a smaller scale. There is no non-sweeping button anywhere in this system.

Hover text is black, never white. White on accent is 2.50:1; black is 8.39:1. Honours prefers-reduced-motion by filling instantly instead of sweeping.

Outline is the default. .solid inverts it for a single primary action per view — use sparingly. .sm is for topbars and dense UI.

Known cost of 1.5px, accepted. A border cannot occupy half a device pixel, so the browser rounds it. On a 2x display it renders as 3 device pixels, which is the intended lighter weight. On a 1x display it rounds down to 1px — identical to the structural border, so buttons stop out-weighing panels and table grids. You are choosing "3 device pixels on modern screens, 2 on the rest". At 110% or 125% browser zoom it can round either way. If a future audit shows meaningful 1x traffic, revisit the weight then — but not by reaching for another fraction: 1.25px and 1.75px never resolve cleanly at any common ratio.
Implementation note. The border weight lives in --btn-bw and the line-height is calc(3em - (var(--btn-bw) * 2)). Earlier revisions hard-coded calc(3em - 4px), which silently pushes the label off centre the moment the weight changes. Never hard-code it again.

[ SHAPE ]
Radius, borders, icons
Icon stroke is 1.75, size is 20px — 18px inside a section rule. The stroke sits between the previous values of 1.5 and 2. Unlike the button border, an SVG stroke is antialiased rather than snapped to whole device pixels, so 1.75 renders as a genuine intermediate weight at every pixel ratio. There is no display-dependency caveat on this one. The 18px exception is scoped narrowly: it applies only to interactive controls sitting inside a section rule, never to standalone icons.

Lucide, 20px, stroke 1.75. Ink by default, accent when interactive or highlighted.

Border radius0px everywhere. Only exception: macOS traffic-light dots in the terminal component.
Section rule--rule — always clearly visible, brighter than the component border in dark.
Component border--border — terminal, table-grids, panels, footer strip.
Hairline--hairline — quiet dividers, list separators, low-emphasis containers.
Button systemSquare sweep only. .btn, .solid, .sm. No filled, flat or non-sweeping button exists anywhere.
Button border1.5px via --btn-bw. One weight for every button. See §04 for the accepted cost.
IconsLucide only, strokeWidth={1.75}. size={20} standalone; size={18} for a control embedded in a section rule, where 20px overpowers the 11px eyebrow. Ink by default, accent when interactive.
Mode toggleBare Lucide sun/moon — no background, no border, no track; hover turns it accent. A pill or switch was considered and rejected: it needs rounded corners and would cost a second exception to the 0px rule.
Toggle positionAlways the final element on the right of any bar. Nothing comes after it. Actions sit immediately before it.
Focus ring1px solid --accent, outline-offset:3px. Deliberately lighter than the 1.5px border — it sits outside the element and only appears on keyboard focus.
Selection cue1px accent border marks the active item; any paired marker is a square ■, never a round bullet.
GradientsNever. Any kind, anywhere. Use flat colour, texture or layering instead.

# Multiplexer routing: guaranteed for every agent

Written 2026-11-25. Problem: agents miss the rule "in Herdr, delegated agents and long or
background jobs run as visible multiplexer children", so the owner repeats it in every session.
Cause: the rule is conditional and buried (global AGENTS.md "Model tiering and delegation",
"before driving panes, run agent-mux"), and the `herdr-app` / `delegate-visibly` skills only load
when their description matches. After a resume or compaction the skill text is gone. Meanwhile each
harness offers its own background and subagent features, and nothing stops their use.

Goal: no repetition, for Claude, opencode, omp and (as far as its hooks allow) Codex, in fresh,
resumed and compacted sessions.

## Owner decisions (2026-11-25)

- Scope: every delegated agent (including general-purpose, Explore and review subagents) and every
  long or background job (tests, builds, servers, watchers, local CI). Quick commands (ls, cat,
  git status) stay normal tool calls.
- Enforcement: block the harness's own background and subagent features and redirect with the
  exact command to run instead, plus inject the rules at session start, resume and compaction.
- Hosts: Herdr Core (`hc`, agent-mux prints `herdr-app`) and the legacy Herdr TUI (`herdr`,
  agent-mux prints `herdr`, which has worktrees). Outside both (`none`), nothing changes.
- Later: `rex` as a third host. Design the host detection and rule text so a host is one table
  entry, not a rewrite.

## Design

One host-aware component, three layers, the same for every harness.

1. **`agent-mux` stays the single source of host truth.** Add `agent-mux --rules` (or a sibling
   script `agent-mux-rules`) that prints the short rule block for the detected host, or nothing for
   `none`. Rule text lives in one place per host (a small table/heredoc per host: herdr-app, herdr,
   later rex). Keep the block under ~15 lines: what goes through the multiplexer, the exact command
   shapes (`hc run --bg --name <slug> --cwd <dir> -- <cmd>` / `herdr agent start ...` per the
   delegate-visibly skill), and which skill to load for details.
2. **Inject at session start, resume and compaction.**
   - Claude: `SessionStart` hook (matchers startup, resume, clear, compact) that runs
     `agent-mux --rules` and returns it as additional context. Install it where every session reads
     it on the agent host: the managed settings generated by
     templates/agent-permissions/generate.py (agent-host), plus the user/standard bundles if cheap.
   - opencode: extend opencode/.config/opencode/plugins/ with a plugin that injects the rule text
     into the system prompt (verify the plugin API on the installed version).
   - omp: extend the existing templates/agent-guard/adapters extension (or a sibling) with a
     session-start/system-prompt injection (verify the omp 19.1 extension events).
   - Codex: use a pre-tool or session hook if the installed Codex supports one; otherwise the text
     layer only, documented as the gap.
3. **Block and redirect** (only when the host is herdr-app or herdr):
   - Claude: PreToolUse deny for `Bash` with `run_in_background: true`, the `Agent`/`Task` tool,
     and `Workflow`, with a reason naming the exact hc/herdr command. Put this in the shared guard
     (templates/agent-guard/agent_guard.py) as a host-aware check so every adapter gets it, or in a
     small dedicated hook if the guard's Bash-only input does not fit; justify the choice.
   - opencode: block the `task` (subagent) tool and any bash background option in the plugin.
   - omp: block its task/subagent tool and background bash in the extension.
   - Commands already going through `hc run` / `herdr agent start|pane run` are never blocked.
   - Host detection must be cheap and cached per session (agent-mux calls hc/herdr); a failure to
     detect means `none` (fail open for routing: this is a workflow rule, not a security boundary).
4. **Text layer.** Replace the buried AGENTS.md passage with a short unconditional block near the
   top of agents/.agents/AGENTS.md: "In Herdr Core or the Herdr TUI, run delegated agents and
   long/background jobs as multiplexer children; your harness enforces this and tells you the
   command." Fix the herdr-app and delegate-visibly skill descriptions so they trigger on
   "subagent", "background", "test suite", "server", not only on agent-mux output.
5. **Sandbox grants.** agent-launch sessions must be able to run agent-mux and drive the host:
   the herdr-core socket is granted; add the legacy herdr server socket to pi-agent-host.json
   (find its path from the herdr CLI/config) so herdr detection and pane control work under nono.

## Acceptance

- `agent-mux --rules` prints the herdr-app block in an hc terminal, the herdr block in a herdr pane,
  nothing elsewhere (test with faked inputs where a live host is unavailable).
- Claude: in herdr-app, a Bash call with run_in_background and an Agent tool call are denied with the
  hc command in the reason; outside Herdr both are allowed. SessionStart output appears on startup and
  resume (hook unit test with sample payloads).
- opencode and omp: the task/subagent tool is refused in herdr-app with the redirect message; the rule
  block is injected (unit test the plugin/extension functions; live check commands listed for the owner).
- Codex: documented capability and what was done.
- generate.py --check and the guard selftest stay at 0 failures.
- Live owner checks listed: fresh session, resumed session, compacted session in hc, in a herdr pane,
  and outside Herdr, for Claude, opencode and omp.

## Status (2026-11-25): built, uncommitted, not installed

Built on branch chore/sandbox-deny-list; the live checks below still need the owner.

What exists:

- `herdr/.local/bin/agent-mux`: `--rules [host]` prints the host's rule block (6 lines; nothing for `none`). Plain
  `agent-mux` is unchanged. One `rules_<host>` function per host plus one `detect` branch: rex is one of each.
- `herdr/.local/bin/agent-route` (python3, one shared script, not part of `agent_guard.py`): `session-start`
  (additionalContext JSON for Claude and Codex), `rules` (plain text for plugins), `check [--neutral]` (the routing
  check for every harness). The redirect messages are the `HOSTS` table in it (rex = one entry). Why separate from the
  guard: the guard is root-owned, agent-host only, takes a command string, and fails closed; routing must work on
  every machine, takes tool names and flags, and must fail open. Mixing them would give one script two opposite
  failure modes. The guard is untouched (selftest 88 samples, 0 failures).
- Host detection: no `HC_TERMINAL_ID` and no `HERDR_ENV=1` means `none` without any call. Otherwise `agent-mux` runs
  once and the answer is cached per terminal (`$XDG_RUNTIME_DIR/agent-route-<uid>/`): a found host for 1 h, `none`
  for 5 min. Any failure (no agent-mux, no hc, bad payload, unwritable cache) is allow, exit 0.
- Blocked in herdr-app and herdr: Claude `Bash` with `run_in_background`, `Agent`, `Task`, `Workflow`; opencode `task`
  and bash `background: true`; omp `task` and bash `async: true`; Codex `spawn_agent` (name seen in the binary, unverified
  as a hook tool name). A Bash command whose first word (after VAR=value) is `hc` or `herdr` is never blocked, so
  `herdr agent wait` in a background Bash call (delegate-visibly) still works.
- Claude: generate.py adds a `SessionStart` hook (matcher `startup|resume|clear|compact`) and a `PreToolUse` hook
  (matcher `Bash|Agent|Task|Workflow`) to every bundle and the agent-host managed settings (identical hooks from several
  layers are de-duplicated by Claude Code). Both run `$HOME/.local/bin/agent-route` and exit 0 if it is missing.
  `generate.py --check` has new checks that run the generated hook commands against faked hosts.
- opencode: `opencode/.config/opencode/plugins/mux-route.ts` (`experimental.chat.system.transform` injects the rules
  on every request; `tool.execute.before` throws the redirect). NOTE: that plugins dir is in this repo's
  `.git/info/exclude`, so git does not show the file.
- omp: `templates/agent-guard/adapters/omp-mux-route.ts` (`before_agent_start` appends to the system prompt,
  `tool_call` returns `{block: true, reason}`); `regen-agent-host.sh` installs it as `~/.omp/agent/extensions/mux-route.ts`.
- Text: AGENTS.md has a short unconditional "Multiplexer routing (Herdr)" block at the top; the old section only points to
  it. herdr-app and delegate-visibly descriptions now trigger on subagent, background, test suite, server, delegation.
  delegate-visibly's "read-only review runs as a hidden subagent" row was changed: inside Herdr the harness now refuses
  hidden subagents, so read-only workers also get a pane (owner decision: every delegated agent).
- nono: `pi-agent-host.json` gets `unix_socket_subtree: $XDG_CONFIG_HOME/herdr/sessions` (named herdr sessions keep
  `herdr.sock` at `~/.config/herdr/sessions/<name>/herdr.sock`; `herdr status` shows the default session's socket as
  `~/.config/herdr/herdr.sock`).

Verified API facts (installed versions): Claude Code 2.1.332 SessionStart `source` is startup|resume|clear|compact|fork
and `hookSpecificOutput.additionalContext` is accepted; Task is an alias of the Agent tool; tools are `Agent`,
`Workflow`, `Bash` (`run_in_background`). opencode plugin 1.18.5: `experimental.chat.system.transform`,
`tool.execute.before` (throw to block), subagent tool `task`, bash arg `background`. omp (types in
pi-coding-agent 18.14.0 on disk; the `omp` binary is a separate build, so 19.1 was not inspected):
`before_agent_start` result `systemPrompt: string[]`, `tool_call` result `{block, reason}`, tool `task`, bash input
`async`. Codex 0.171.0: `hooks` feature is stable and on; `~/.codex/hooks.json` uses the Claude layout; events include
SessionStart (additionalContext), PreToolUse, PermissionRequest, PreCompact, PostCompact, SubagentStart.

Remaining gaps:

- Codex: hooks are ready but not live (the sandbox cannot write `~/.codex`). Verified against Codex's hooks docs and the
  0.171 binary strings: payload fields are session_id, turn_id, transcript_path, cwd, hook_event_name, model,
  permission_mode, tool_name, tool_input, tool_use_id; shell and exec_command both report tool_name `Bash` (tool_input.command,
  no background flag); subagents report `spawn_agent` (`Agent` is only a matcher alias); deny uses the same
  `hookSpecificOutput.permissionDecision: deny` JSON as Claude; SessionStart accepts `hookSpecificOutput.additionalContext`.
  `agent-route` already handled this shape; Codex cases were added to the tests and pass. `templates/codex-hooks/hooks.json`
  is the live file plus a SessionStart entry and a PreToolUse entry with matcher `^spawn_agent$` (Bash is not matched: Codex
  has no background flag, so nothing could be routed and every shell call would pay a python start). Install:
  `cp ~/dotfiles/templates/codex-hooks/hooks.json ~/.codex/hooks.json`, then confirm live that a Codex `spawn_agent` is
  denied inside Herdr. Codex long-running shell jobs are not covered (text rules only).
- A shared opencode server started outside Herdr (systemd) sees no Herdr in its own environment, so it injects and
  blocks nothing; a `--standalone` server started by agent-launch inside the terminal does.
- omp's `agent()` call inside the eval tool, and omp's automatic background of a long foreground bash, are not covered.
- Claude workers started by `hc run` are themselves under herdr-app, so they cannot use the Agent tool either (matches
  "workers do not delegate further without authorization").
- The herdr socket grant is the sessions subtree only; the default session socket does not exist while that server is
  down, and nono needs exact existing paths for a single socket. TypeScript type-checking of the two TS files was not
  run (only an old tsc is installed); they bundle with bun and run against stubs.
